01 · Mapa del sistema

Todos los agentes de un vistazo

El usuario solo interactúa con Kairós como una sola entidad. Por debajo, el Core Agent orquesta a los 8 especializados según el contexto real del usuario en cada momento.

02 · Agente principal

Core Agent

⚡
CORE · orchestrator.py · agent-service/agent/
Core Agent — orquestador
Activo en cada interacción. Es el único que el usuario ve y con quien habla.
Siempre activo
Tarea exacta
Construir el UserContext completo desde Supabase al inicio de cada mensaje
Evaluar el árbol de triaje hardcoded antes de llamar al LLM — ahorra tokens y latencia
Decidir qué agente especializado responde según contexto + mensaje
Generar la respuesta final que ve el usuario con el tono correcto
Actualizar el estado del sistema tras cada interacción
Datos del onboarding que consume
PHQ-9 score — determina el umbral de intervención emocional desde el día 1
GAD-7 score — calibra cuándo activar el protocolo de derivación
Perfil de pantalla — screen_hours basal, apps de riesgo, patrón nocturno
Hábitos digitales iniciales — hora de dormir, energía, concentración habitual
Tipo de perfil (teen/young/adult) — adapta el tono de todos los agentes
Neurociencia El PHQ-9 y GAD-7 son instrumentos validados que mapean directamente sobre el eje hipotálamo-hipófisis-adrenal (HPA). Conocer el score de base le permite al Core calibrar si el sistema nervioso del usuario está en modo "aprendizaje" o modo "supervivencia" — dos estados donde el cerebro procesa la información de forma radicalmente diferente. Fuente: Sapolsky, R. — Why Zebras Don't Get Ulcers (2004)
Cómo actúa con esa información a futuro
Si el PHQ-9 sube respecto al baseline → escala la frecuencia de check-ins del Mood Agent
Si el GAD-7 ≥ 15 en cualquier punto → deriva a Línea 106 sin pasar por el LLM
El perfil de pantalla del onboarding se convierte en el "normal" del usuario — las anomalías se detectan contra ese baseline, no contra promedios globales
Actualiza la fase del usuario (1→2→3) según días activos acumulados
03 · Agentes especializados

Los 8 agentes

Cada uno tiene una responsabilidad exclusiva, consume un subconjunto específico de los datos del usuario, y actúa en un momento concreto del día. Ninguno puede sobrepasar al Mood Agent si hay señales de crisis.

🌅
AGENT 01 · morning_agent.py
Morning Agent
Primera apertura del día antes de las 11am · si lleva 3+ días sin abrir: primero pregunta qué pasó
Diario · mañana
Tarea exacta
Establecer el estado base del día en máximo 3 preguntas
Detectar si hubo días sin actividad y preguntar qué pasó — sin culpa
Pausar la racha si el usuario lleva 3+ días fuera (no borra, pausa)
Entregar morning_mood, sleep_quality, wake_time, has_event_today al Core
Preguntas del check-in matutino
Q1¿Cómo dormiste anoche? (1 al 5)
Q2¿Cómo estás ahora mismo? (1 al 5)
Q3¿Tienes algo importante hoy? (examen / entrega / reunión / día normal)
Datos del onboarding que usa como contexto
Hora habitual de acostarse — si el usuario reportó dormir tarde habitualmente, no se sorprende si la energía es baja
Horas de sueño habituales — distingue "hoy fue mal día" de "siempre duerme poco"
PHQ-9 score inicial — si el baseline ya era bajo, un 2/5 de ánimo no dispara alarma inmediata; si el baseline era alto, sí
Neurociencia — por qué importa el check-in matutino Las primeras horas del día determinan los niveles de cortisol basal. Un check-in matutino no es solo recolección de datos — es una intervención de regulación: al nombrar el estado emocional se activa la corteza prefrontal ventrolateral, que reduce la actividad de la amígdala. Preguntarle al usuario cómo está lo ayuda a procesar su estado antes de que el día lo abrume. Fuente: Lieberman et al. (2007) — UCLA, Psychological Science
Cómo actúa con esa información a futuro
El morning_mood se convierte en el punto de partida para el Mood Agent — si cae consistentemente por debajo del baseline del onboarding, el Core escala la frecuencia
has_event_today activa el Focus Agent con mayor prioridad durante ese día
Después de 7 días de check-ins, el Insight Agent tiene suficientes datos para generar la primera correlación real
Los días sin check-in le informan al Progress Agent sobre riesgo de abandono
REGLA: Si days_since_active ≥ 3 → no lanzar el check-in directamente. Primero: "Llevas unos días, ¿qué pasó?" — sin presión, sin racha rota.

AGENT 02 · sleep_agent.py
Sleep Agent
Check-in matutino + rutina de cierre a las 22:00 + cuando el usuario menciona cansancio o sueño
Mañana y noche
Preguntas que hace
M1¿Cuántas horas dormiste aproximadamente?
M2¿Cuánto tardaste en quedarte dormido? (poco / bastante / mucho)
M3¿A qué hora miraste el teléfono por última vez antes de dormir?
N1¿A qué hora piensas acostarte hoy?
N2¿Cómo estuvo tu energía durante el día? (1 al 5)
REGLA: Si sleep_hours < 5 AND hora > 21:00 AND usuario quiere estudiar → bloquear Focus Agent. Decirle la verdad.
Datos del onboarding que usa
Hora habitual de acostarse — define qué es "tarde" para este usuario específico, no un promedio global
Horas de sueño habituales — el baseline de sueño permite detectar deuda acumulada (sleep debt)
Uso nocturno de pantalla (onboarding screen) — si ya reportó usar el teléfono en la cama siempre, la recomendación es diferente que si es algo nuevo
Neurociencia — sueño y aprendizaje La fase REM consolida lo aprendido durante el día mediante replay hipocámpico. Sin sueño suficiente, la potenciación a largo plazo (LTP) — el mecanismo físico de la memoria — se deteriora. Con 6h de sueño durante 14 días, el deterioro cognitivo equivale al de 48h sin dormir, pero el usuario no lo percibe. La amígdala se vuelve 60% más reactiva con privación, amplificando la ansiedad. Fuente: Walker, M. — Why We Sleep (2017, UC Berkeley)
Cómo actúa a futuro
Calcula sleep debt acumulada — si el usuario lleva 3 noches con menos de 6h, la deuda afecta el umbral de intervención del Core
Detecta el patrón exacto que rompe el sueño de este usuario — puede ser pantallas, hora de cenar, ansiedad nocturna
Propone UN solo cambio a la vez — nunca listas. Basado en la ciencia de la formación de hábitos: un cambio a la vez tiene 3x más probabilidad de mantenerse
El Insight Agent usa el historial de sueño para la correlación más importante: sueño → rendimiento académico → estado de ánimo

AGENT 03 · mood_agent.py
Mood Agent
Check-in emocional diario + análisis de tono en cada mensaje + override total si hay señales de crisis
Override de crisis
Preguntas que hace
D1¿Cómo está tu ánimo ahora mismo? (1 al 5)
D2¿Hay algo que te esté pesando hoy?
D3¿Cómo está tu nivel de estrés? (1 = tranquilo, 5 = al límite)
D4*¿Te has sentido así varios días seguidos o es de hoy? (solo si ánimo ≤ 2)
D5*¿Dormiste con pensamientos dando vueltas? (solo si ánimo ≤ 2)
REGLA CRÍTICA: Si crisis_keywords OR PHQ-9 ≥ 15 → triggerCrisisProtocol() — Línea 106. Irrompible. Sin LLM.
Datos del onboarding que usa
PHQ-9 score inicial — es el baseline emocional. Un 3/5 de ánimo en alguien con PHQ-9 basal de 3 es muy diferente a un 3/5 en alguien con PHQ-9 basal de 12
GAD-7 score inicial — calibra el umbral de ansiedad. Si el GAD-7 basal ya era alto, una respuesta ansiosa en el chat no es anómala — pero una subida sí lo es
Respuesta a Q5 del screen — "¿Cómo te sientes después de redes?" Si reportó "más ansioso" o "me comparo más", el Mood Agent tiene contexto para conectar el estado emocional con los patrones digitales
Neurociencia — nombrar las emociones El "affect labeling" — poner palabras a los estados emocionales — reduce la actividad de la amígdala y activa la corteza prefrontal ventrolateral, el sistema ejecutivo del cerebro. No es solo terapéutico: es un mecanismo neurobiológico documentado. Por eso las preguntas del Mood Agent son conversacionales, no formularios — la forma importa tanto como el contenido. Fuente: Lieberman et al. (2007) — "Putting Feelings into Words", Psychological Science
Cómo actúa a futuro
Calcula mood_trend de 7 días — si el promedio cae respecto al baseline del onboarding, el Core aumenta la frecuencia del check-in emocional
Los emotional_keywords detectados en conversación libre alimentan el modelo XGBoost del ML Worker para predecir si el PHQ-9 va a empeorar en los próximos 7 días
Si el mood está bajo, el Mood Agent pausa todos los demás agentes — no tiene sentido hablar de hábitos cuando el sistema nervioso está en crisis
La conexión redes → estado emocional se construye con el tiempo: si los días con alto screen_hours correlacionan con mood bajo, el Insight Agent lo detecta y lo nombra

AGENT 04 · focus_agent.py
Focus Agent
Cuando el usuario quiere estudiar o el Core detecta evento importante hoy
Reactivo + proactivo
Preguntas que hace
F1¿Cuánto tiempo tienes disponible ahora mismo, sin interrupciones? (siempre primera)
F2¿Qué necesitas estudiar o hacer?
F3¿Cómo te sientes para arrancar? (listo / un poco bloqueado / no puedo)
F4¿Tienes el teléfono cerca o en otro cuarto?
F5Al terminar: ¿qué es lo único que vas a recordar de lo que hiciste? (guarda en DB)
REGLA: Si F3 = "no puedo" AND tono del mensaje = ansiedad → derivar a Mood Agent primero. Nunca forzar sesión en estado ansioso.
Datos del onboarding que usa
"¿Con qué frecuencia sientes que no puedes concentrarte?" — calibra el umbral normal. Si el onboarding reveló dificultad frecuente, las sesiones empiezan en 8 min, no en 12
Intereses del perfil — conecta los temas de estudio con lo que el usuario ya dijo que le importa. Derivadas + diseño de videojuegos. Historia + podcasts favoritos. Hace el contenido relevante.
Energía habitual del día — si reportó energía media-baja, las sesiones se proponen en el momento del día con mejor energía histórica
Neurociencia — atención sostenida y dopamina El sistema de recompensa del cerebro (núcleo accumbens) espera recompensa inmediata después de años de scroll. Las sesiones de 8-12 minutos son una re-calibración gradual: suficientemente cortas para no disparar la respuesta de "esto es aburrido", suficientemente largas para que el cerebro empiece a asociar el esfuerzo sostenido con una recompensa (completar algo). El recall final — "¿qué recuerdas?" — es el cierre del ciclo dopaminérgico de la sesión. Fuente: Mark, G. et al. (2016) — UC Irvine + Leroy, S. (2009) — UW, Attention Residue
Cómo actúa a futuro
El recall de cada sesión se guarda en DB — el Focus Agent lo usa en la siguiente sesión del mismo tema para conectar lo nuevo con lo que ya se procesó
El block_type (anxiety / fatigue / distraction) acumula datos: si el bloqueo es siempre ansiedad, el Insight Agent lo detecta y lo conecta con el PHQ-9
Las sesiones completadas alimentan al Isolation Forest del ML — días sin sesiones son una señal de anomalía que puede indicar deterioro de ánimo
Semana a semana, la duración de las sesiones aumenta gradualmente — el cerebro re-aprende a sostener la atención

AGENT 05 · screen_agent.py
Screen Agent
Check-in de tarde (17:00) + cuando la extensión detecta uso prolongado + cuando el usuario menciona redes
Extensión + autorreporte
Preguntas que hace (si no hay extensión)
S1¿Cuántas horas llevas en pantallas hoy?
S2¿Fue más uso intencional o scroll sin fin?
S3*¿Cómo te sientes después de haber estado en redes? (si screen_hours > 3)
Datos automáticos de la extensión
Total de tiempo en pantalla por dominio y categoría
Velocidad de scroll — doomscrolling si supera 800 px/s por más de 5 min
Cambios de pestaña por hora — fragmentación si supera 20/h
Uso nocturno — ratio de actividad después de las 22:00
Datos del onboarding que usa
Captura / respuestas de screen time — establece el baseline de uso. Lo que ahora el sistema considera "más que normal" es relativo a ese baseline, no a promedios globales
"¿Cómo te sientes después de redes?" (Q5 onboarding) — si el usuario ya reportó ansiedad o comparación, el Screen Agent lo conecta directamente con el Mood Agent
Apps principales — si Instagram y TikTok están en el top 3, el playbook doomscrolling se carga con más contexto
Neurociencia — scroll y dopamina intermitente El diseño del scroll infinito usa el mismo mecanismo de refuerzo variable que las máquinas tragamonedas (Skinner, 1938). El núcleo accumbens se activa con la anticipación de la recompensa, no con la recompensa misma. Cada pull-to-refresh es un tirón del brazo de la máquina. El Screen Agent no bloquea — hace visible el patrón, porque la conciencia activa la corteza prefrontal, que puede inhibir el impulso. Fuente: Sherman et al. (2016) — UCLA fMRI study, Psychological Science
Cómo actúa a futuro
El nocturnal_ratio es la señal más correlacionada con la calidad del sueño — si sube, el Sleep Agent recibe una alerta automática
El Isolation Forest analiza los patrones de screen_hours — un día con 8h cuando el promedio es 3h es una anomalía que puede indicar evasión emocional
La pregunta central del agente — "¿elegiste esto o simplemente pasó?" — es el mecanismo de conciencia que, con el tiempo, reduce el uso compulsivo sin restricciones
Los datos de la extensión alimentan directamente el modelo XGBoost: screen_hours + nocturnal_ratio son features predictores del cambio en PHQ-9

AGENT 06 · fuel_agent.py
Fuel Agent
Check-in de tarde + si horas_sin_comer supera 8h + usuario menciona cansancio físico o bajón de energía
Tarde · reactivo
Preguntas que hace
E1¿Ya comiste algo hoy? (sí / no / algo pequeño)
E2¿A qué hora fue tu última comida?
E3¿Cómo está tu energía física ahora? (1 al 5)
E4¿Tomaste suficiente agua hoy? (sí / más o menos / casi nada)
E5¿Hiciste algún movimiento físico hoy? (así sea caminar)
REGLA: Si hours_since_last_meal > 8 → fuel_block_flag = true. Core bloquea Focus Agent hasta que el usuario confirme que comió.
Datos del onboarding que usa
"¿Comes regularmente?" (onboarding hábitos Q5) — si el usuario ya reportó saltarse comidas frecuentemente, el agente no se sorprende: ajusta el umbral de intervención
Energía habitual del día — si el baseline de energía ya era bajo, un 2/5 no es una alarma inmediata; si era 4/5 y ahora es 2/5, sí lo es
Neurociencia — intestino y cerebro El 95% de la serotonina del cuerpo se produce en el intestino (eje intestino-cerebro). El nervio vago conecta directamente el estado del microbioma con el estado emocional. Saltarse el almuerzo genera hipoglucemia cerebral — el cerebro sin glucosa busca dopamina fácil (scroll, azúcar) y entra en ciclos de picos y bajones que destruyen la concentración. El bajón de las 3pm no es cansancio — es glucemia. Fuente: Cryan et al. (2019) — Nature Reviews Neuroscience
Cómo actúa a futuro
Construye correlaciones entre comidas y rendimiento: "los días que desayunaste, tus sesiones de foco duraron el doble" — datos propios, no estadísticas genéricas
El movimiento físico se correlaciona con mood_score — el Insight Agent detecta si los días con actividad física tienen consistentemente mejor ánimo
El fuel_block_flag le dice al Core cuándo el cansancio reportado es metabólico, no emocional — evita que el Mood Agent intervenga en algo que se resuelve comiendo

AGENT 07 · insight_agent.py
Insight Agent
Cada 7 días automáticamente, sin que el usuario haga nada. No hace preguntas — analiza los logs.
Automático · semanal
Qué consume
Todos los DailyLogs de los últimos 7 días: sleep_hours, mood_am, mood_pm, screen_hours, meals_count, focus_sessions, physical_energy
Historial de sesiones de estudio — temas, duraciones, recalls guardados
Rachas y días activos del Progress Agent
PHQ-9 / GAD-7 del onboarding como baseline de comparación
Qué produce
1 narrativa personalizada generada por Claude con datos reales del usuario — nunca estadísticas genéricas
3 correlaciones de sus propios datos: sueño→ánimo, pantallas→sueño, comida→foco
1 recomendación para la próxima semana — la más impactante según los patrones detectados
Progreso comparado con la semana anterior y con el baseline del onboarding
Neurociencia — feedback personalizado y motivación El cerebro responde de forma muy diferente a feedback genérico ("duerme 8 horas") versus feedback de sus propios datos ("cuando dormiste +7h, tu ánimo fue 40% mejor"). El segundo activa el sentido de agencia — la creencia de que las propias acciones tienen consecuencias — que es el predictor más fuerte de cambio de comportamiento a largo plazo según la Teoría Social Cognitiva de Bandura. Fuente: Bandura, A. (1997) — Self-Efficacy: The Exercise of Control
Ejemplo de output real
Insight semanal generado "Esta semana dormiste 1.4h más que la anterior. Los 3 días que dormiste más de 7h estudiaste el doble y tu ánimo promedió 4/5. El martes fue tu mejor día — coincide con que desayunaste y no abriste TikTok antes de las 11am. Para la próxima semana: teléfono fuera de la cama."

AGENT 08 · progress_agent.py
Progress Agent
Al abrir el dashboard + calcula fases + detecta riesgo de abandono
Dashboard · fases
Qué calcula
Racha actual de días activos y racha más larga histórica
Fase del usuario: Fase 1 (días 1-14, básico), Fase 2 (días 15-60, correlaciones), Fase 3 (60+, retos)
Tendencias de 14 días para cada variable del DailyLog
Riesgo de abandono si lleva 3+ días sin actividad
ANTI-ABANDONO: Si days_since_active ≥ 3 → racha pausada (no borrada). Mensaje al volver: "¿Qué pasó?" — sin culpa, sin presión.
Sistema de fases
Fase 1 (días 1-14): interfaz simple, solo check-ins y chat. El sistema observa sin abrumar.
Fase 2 (días 15-60): se desbloquean correlaciones e insights profundos. El usuario ya tiene datos suficientes para ver patrones reales.
Fase 3 (día 60+): el tono cambia. Ya no guía — reta. El usuario ya conoce el sistema; ahora lo usa con autonomía.
Neurociencia — hábitos y refuerzo gradual La formación de hábitos requiere en promedio 66 días (Lally et al., 2010, UCL), no 21 como dice el mito popular. El sistema de fases está calibrado sobre esta evidencia: los primeros 14 días son de observación, los siguientes 45 días son donde el hábito se consolida, y a partir del día 60 el comportamiento es más automático. Las rachas aprovechan el efecto de consistencia conductual — una racha rota no se borra, se pausa, porque el reinicio total destruye la motivación. Fuente: Lally et al. (2010) — European Journal of Social Psychology, UCL
Cómo actúa a futuro
Alimenta el dashboard con las gráficas de progreso de los últimos 14 días
Le dice al Core en qué fase está el usuario para que el tono de respuesta sea diferente — no se le explica lo básico a alguien en Fase 3
El riesgo de abandono activa un mensaje de re-engagement específico según los datos: si el usuario siempre abandona después de un día con mal ánimo, el mensaje lo menciona

05 · Árbol de triaje

Cómo decide el Core qué agente responde

Las reglas P1–P8 se evalúan en microsegundos sin llamar al LLM. Solo si ninguna aplica, Claude decide con el UserContext completo. Esto hace el sistema rápido, predecible y barato en tokens.

P1 crisis_flag = true OR crisis_keywords en mensaje → Mood con protocolo de crisis. Línea 106. Irrompible. Sin LLM.
P2 mood_score < 3 OR mood_am < 3 → Mood Agent toma el control. Todos los demás agentes pausan.
P3 fuel_block_flag = true (hours_since_meal > 8) → Fuel Agent. Core bloquea Focus hasta que el usuario confirme que comió.
P4 sleep_hours < 5 AND hora > 21 AND intent = "estudiar" → Sleep Agent. Honestidad sobre obediencia: "con este estado no va a entrar nada".
P5 screen_hours > 3 AND has_exam_tomorrow = true → Screen Agent con el contexto del examen de mañana.
P6 physical_energy < 2 AND hours_since_meal > 6 → Fuel Agent. El cansancio es glucémico, no emocional.
P7 sleep_quality < 2 AND usuario pide estudiar → Sleep Agent. No se fuerza sesión de foco con sueño de 1/5.
P8 nocturnal_ratio > 0.4 (más del 40% de uso después de las 22h) → Sleep Agent con playbook nocturnal-use-pattern.
P99 Ninguna regla hardcoded aplica → Claude LLM decide con UserContext completo. El fallback inteligente.
Por qué primero reglas y luego LLM Las reglas P1-P8 garantizan que los casos de mayor riesgo — crisis emocional, sin comer, sin dormir — siempre se manejen correctamente, sin depender de que el LLM interprete bien el contexto. El LLM es poderoso pero no predecible al 100%. Para las decisiones críticas, las reglas explícitas son más seguras, más rápidas y más auditables. El LLM entra donde la nuance importa más que la velocidad.
